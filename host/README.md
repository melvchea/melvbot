# host

Host-side tooling for working on melvbot with Claude Code. `bin/` is on `PATH`.

## Helpers
No model is used by any helper. `digest`, `webx` and `big-output-nudge` were removed 2026-10-25 (the MiniMax helpers were already disabled on 2026-10-19; `dexplore` and `offload-guard` were removed earlier). Main session Sonnet 5.5, `coder` Haiku 5.5 (see CLAUDE.md "Model routing"). All helpers take `-h`/`--help` and return the exit status of the command they ran.
- `dverify [--check|--all]`: default is typecheck plus the touched tests; `--check` runs plain tsc only (first 40 error lines on failure); `--all` runs typecheck and then the full suite (counts on pass, last 60 lines on failure; CI runs the same suite); `ddeploy` calls `dverify --check` and `dverify --all`
- `dbuild`: `docker compose build`, prints `build: ok` or the last 40 lines on failure; uses the built-in `default` buildx builder (docker driver) with `COMPOSE_BAKE=true` (override with `BUILDX_BUILDER`, `COMPOSE_BAKE`)
- `ddeploy [--dry-run] [--no-ci] [service ...]`: first refuses unless `libexec/ci-gate` reports the GitHub CI run of HEAD as `pass` (`wait`/`fail` exit 1; push and wait for green, or `--no-ci` to skip), then `dverify --check && dverify --all` only with `--no-ci` or a dirty container, then `dbuild`, `docker compose up -d melvbot [services]`, waits up to 30s for a stable container, then the doctor probe filtered to non-ok lines (no LLM); refuses when tracked files differ from HEAD (unless `--no-ci`), tags the built image `melvbot-ts:<short-sha>`, prints the total time, tags the running image `melvbot-ts:prev` first and rolls back to it if the container is unstable or the probe fails; stops at the first failing step ("ddeploy: <step> failed", that step's exit code)
- `dalerts`: open GitHub code-scanning (CodeQL) alerts grouped by severity (`#n rule path:line`), exit 1 if any; no LLM. OpenSSF Scorecard alerts (weekly workflow) are listed under "scorecard (informational, not gating)" and never fail the gate. The CI job `code-scanning alerts` runs it after CodeQL finishes for the pushed commit, so any open alert turns CI (and the `ddeploy` gate) red. Per severity, ask a yes/no AskUserQuestion before fixing (CLAUDE.md).
- CI (`.github/workflows/ci.yml`, default `permissions: {}`, `contents: read` per job): `container ts` (build, tests with coverage), `secret-guard` (guard + gitleaks), `workflow-lint` (zizmor), `shellcheck + hadolint` (warning level, hadolint ignores DL3008), `dependency-review` (PRs only, fails on high), `code-scanning alerts` (waits for CodeQL, runs `dalerts`). `weekly-scan.yml` (Sat 21:17 UTC, or `gh workflow run "Weekly scan" -R melvchea/melvbot`): Trivy fs + Dockerfile (gating alerts) and OpenSSF Scorecard (informational). Secret-scanning generic-password and validity-check options are paid, not enabled; private vulnerability reporting is a manual repo setting.
- `dci [--wait]`: CI runs for HEAD plus all open alerts (CodeQL via `dalerts`, Dependabot, secret scanning), exit 1 if a run failed or any alert is open; `--wait` polls up to 10 min for the runs to finish. The `PostToolUse` hook `libexec/post-push-ci` (`.claude/settings.json`) runs `dci --wait` after every `git push` and hands the result to Claude; silent for other commands. Use `dci` by default (after a push, or any "show CI and alerts" ask); use `dalerts` alone only for a quick CodeQL/Scorecard check (CI runs it as the gate). No LLM
- `ddb <cron|nudges|conversation|path> "<sql>" | .tables | .schema <t>`: read-only SQLite (SELECT/PRAGMA/WITH only), tab-separated with header; no LLM
- `dverify` (no argument): typecheck, then the test files touched by the git diff (changed tests, plus tests matching or importing changed `src` files); one line on pass, first failure on fail. `dverify` is the only local check
- `dsaved --outcome [days]`: Claude Code $ per day at list prices (cache writes at the 5m rate) next to git commits that day, and $ per commit
- `dsaved [days]`: Claude Code tokens per day and model from the transcripts, tokens saved by helpers (default 7 days, per day and caller, % of that day's tokens; data in `~/.local/state/melvbot/helper-usage.tsv`), then Telegram SDK turns, tokens and no-LLM intercepts per day from `turn_log`; no LLM. The helper-savings rows are history only (digest and webx were removed; no new rows are written).
- Intercept miss check (weekly): `ddb conversation "select substr(created_at,1,10) d, substr(replace(prompt,char(10),' '),1,90) p from turn_log where route='claude' and prompt glob '[sSlLaAdDuU][hHiIdDeEpP]*' and created_at>=date('now','-7 day') order by id desc"`, read for show/list/add/delete/update phrasings that should have matched; per-route hits come from `dturns`. Remove an intercept only after 30 days of zero hits.
- `dturns [days] [raw]`: the turn log (`raw` prints all of it; default is the last 80 Claude turns, 220 chars each, no model): what the Telegram bot spent Claude quota on, so recurring intents can be spotted by eye; the last line also counts `intercept:<name>` hits (instant features used). Ends with a plain-number "Search & fetch" section parsed from `docker logs` of melvbot (web_search per-route count and p50/p95 ms, web_fetch backend p50/p95 and in-process fallback rate); logs rotate (10 MB x 3), so long periods may be truncated
- `dsaved --review [days]`: one scorecard (default 7 days) = `--outcome` + top 5 `--sessions` + net helper savings per caller; run it first on any cost/optimisation request and act on rising $/commit, `!` sessions, or a helper with calls but no savings; no LLM
- `dsaved --sessions [days]`: top 20 Claude Code sessions (subagents folded into their parent) by est $ at list prices, with start, assistant msgs and input / cache write / cache read / output, plus commits made during the session (UTC start..last msg; overlapping sessions both count a commit) and $/commit; long sessions show up as huge cache-read totals.

## Token routing (historical; tier 1 disabled, see CLAUDE.md "Model routing")
- Tier 0 non-LLM: `rg`, `head`/`tail`, `jq`, `sed -n`, `git diff --stat`.
- Tier 2 main session edits fully specified changes directly, ≤50 lines per edit; no full-file Write, smallest unique Edit anchor.
- Tier 3 `coder` (Haiku 5.5 medium) for bigger or judgment-heavy work: post the spec, ask "are all requests and decisions in?", launch only after a yes. Pays off only above ~5k saved Opus output tokens or lots of file reading, i.e. when the spec is far shorter than the diff (mechanical or repeated patterns); a 20-50 line edit with a full spec costs about the same either way, so keep it inline. Spec = goal, file:line ranges, verify command. Soft cap 99,990 tokens per coder run, so split an outcome into small tasks (one file or one concern, est. under ~40K tokens each) and launch one coder per task; run coders in parallel only on independent work with disjoint files (never parallel edits to the same file; parallel costs more tokens). Reuse a warm coder via SendMessage while under 99,990 tokens, else start a fresh one.
- Searches: inline `rg`/`sed -n`. Plan inline. Only `coder` is enabled; never `fork`.
- `dsaved --sessions` marks `!` sessions (over $1.5/commit or no commit). Weekly review: `dsaved --review 7`.
- Input: `rg`/`sed -n`/`offset`+`limit`, no whole files or re-reads; long output via `tail`; batch independent calls. Docker, git push, dbuild, ddeploy run as standalone Bash calls (`git -C`, absolute paths, `env X=… cmd`).

## Cost rules (full form of CLAUDE.md "Cost per completed outcome")
- Per MTok: Opus in $4, out $20, cache write $5 (5m) / $8 (1h), read $0.20; Sonnet in $2, out $10, write $2.50 / $4, read $0.10; Telegram bot Haiku 5.5 in $0.10, out $0.50, write $0.125 / $0.20, read $0.01 (5× above 100K-token prompts, so where possible keep Haiku 5.5 usage below 100K tokens); MiniMax is prepaid to 2027-04-28 and now serves only the bot's image and video reading (re-compare with Haiku 5.5 at renewal).
- Redos cost most, so asking first and verifying before reporting done beats saving a call.
- Execution gate: before any edit, `coder` launch, deploy or commit, ask a yes/no AskUserQuestion "Are all prompts and decisions in?" (batched with any open decisions) and proceed only on yes; a later request reopens the gate. Read-only lookups need no gate.
- Output costs 5× input: also no restating plans, specs or tool results, no narration between tool calls; batch edits into one turn, verify once after.
- Cache writes: the MCP set also stays unchanged mid-session; auto-compact at 40%; subagents start cold, use only per Token routing.
- Helpers: never re-run one to re-read output already in context. Bash calls stay standalone (no `cd …;`/`export …;`) so sandbox excludedCommands match.
- Cache reads are cheapest per token but long sessions re-read the whole context every turn (see `dsaved --sessions`); reuse warm context (same coder via SendMessage) over cold starts, but `/clear` once an outcome is done.
- Before re-reviewing Telegram memory, recall or prompt-cache cost, read "Reviewed, no action" in `container/docs/how-to/performance.md` (memory healthy, 1h cache TTL rejected).
- Auto-loaded md (CLAUDE.md, MEMORY.md, `coder.md`) sits in every prefix: one line per rule, no duplicates or examples; details go in on-demand docs (`host/README.md`, `container/docs/`), found with `rg`.
- coder spec: goal, exact file:line ranges, verify command; no pasted files or history. Batch related changes into one launch; don't edit `coder.md` or CLAUDE.md while it runs.

## Claude Code wiring (`~/.claude/settings.json`, not in the repo)
- Agents (`~/.claude/agents/`): `coder` (Haiku 5.5 medium, code needing judgment or changes over 50 lines); `Explore`, `Plan`, `general-purpose`, `claude`, `statusline-setup` and `claude-code-guide` are denied in `.claude/settings.json` so they stay out of the prompt; `coder` is launched only after the user confirms all requests and decisions are in (see CLAUDE.md). The main session edits repo files directly up to 50 lines per Edit (new files up to 50 lines);. `effortLevel: medium`; other subagents default to Haiku (`CLAUDE_CODE_SUBAGENT_MODEL`). Input-token settings (`~/.claude/settings.json`): `MAX_THINKING_TOKENS=0`, `BASH_MAX_OUTPUT_LENGTH=5000`, `autoCompactEnabled` with `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=40`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, claude.ai MCP servers off; cost rules are in CLAUDE.md ("Cost per completed outcome"; the coder's own limits are in `claude/agents/coder.md`).
- `bin/statusline`: model + effort letter (L/M/H/XH/X), context %, Pro 5-hour and 7-day windows as `time left of window, unused %` (e.g. `4.2h/5h 97%l 4.1d/7d 87%l`; context is `2%u`); `Sonnet ` is shortened to `Snn`.
- Custom agents must say `model: haiku` or omit `model`.
